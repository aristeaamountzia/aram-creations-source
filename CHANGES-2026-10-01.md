# Back Office improvements

- Portfolio: drag/drop and accessible up/down buttons save a shared order. The default public Portfolio view uses that order. Static works are merged safely with partial database records.
- Media: "Hero" now reads "Ορισμός ως κεντρική". Uploads have no artificial count limit, including Vinted imports; per-file size and Firestore document size limits still apply. Existing media captions are preserved.
- Navigation: Shop, Portfolio and Back Office use browser history. Back returns to the preceding section.
- Vinted: listing-specific structured availability recognizes numeric or string item IDs. Closed/withdrawn listings are unavailable, without assuming a sale. Failed or blocked requests never infer availability. Refresh preview permits a manual shop price and separate acceptance of availability, favorites and views. Applying a stale preview or changing an item reserved by an order is refused. Title has priority for imported categories.
- Status options: available, reserved, sold and unavailable are shared with the editor/settings. Custom options, hidden options and ordering are saved with shop settings for other devices.
- Cart: unique items, one unit each. No quantity controls, atelier pickup, cash on delivery or Boutique heading. Server rejects removed payment/shipping choices and duplicate quantities. Existing historical cash-on-delivery orders remain manageable.
- Checkout: Firestore transactions prevent two buyers ordering the same piece. Legacy stock above one is treated as one unique piece when ordering. Cancellation releases exactly one piece.
- Order notifications: Resend sends the owner an order number, total and Back Office link. Customer contact/address details stay in Firebase. Notifications are queued transactionally with the order, retried every 10 minutes with a stable idempotency key, and held for review after 23 hours if delivery is still uncertain. The order remains valid if sending fails. The Orders page includes a test-email button.
- History: new changes are stored in private cloud history, with chunked payloads for bulk changes. Undo/redo and restoration refuse conflicting newer changes or active checkout reservations. Existing local history remains available on its original browser.
- Backups: a published Netlify scheduled function snapshots jewelry, portfolio, settings and orders every 30 minutes. Rotating slots retain 24 hours plus seven daily snapshots in private Firebase Storage. Backup now and authenticated JSON download are available in History. Backups include media URLs, not separate copies of binary media. The source code contains the static Portfolio works.

## Verification

`pnpm run lint` and `pnpm run build`.

`pnpm exec tsx --test server/request-check.test.ts server/orders-core.test.ts server/vinted-api.test.ts server/vinted-refresh.test.ts`.

Explicit integration checks use `ORDER_TEST_CREDENTIAL_PATH` pointing to a private local Firebase service-account file. The key must never be committed. Integration checks operate on uniquely named test collections and clean up their own records.

`pnpm exec tsx server/orders-integration.test.ts` checks stock concurrency, idempotency, cancellation and notification retries without sending real mail.

`pnpm exec tsx server/history-integration.ts` checks chunked cloud history, undo/redo, concurrent edits, order reservation guards and anonymous access denial.

`DEPLOY_VERIFY_URL` selects the Netlify deployment for `pnpm exec tsx scripts/verify-deployment.ts`. Set `SEND_OWNER_EMAIL_TEST=1` only when an actual test notification to the owner is intended. It does not create a purchase or change stock.
