# Αντίγραφα και επαναφορά

Η προγραμματισμένη εργασία παραμένει ανά 30 λεπτά. Δημιουργεί αίτημα για το `catalog-backup-worker`, που εκτελεί την αντιγραφή στο παρασκήνιο. Το κουμπί «Backup τώρα» ακολουθεί την ίδια διαδικασία και εμφανίζει πρόοδο, ολοκλήρωση ή συγκεκριμένο σφάλμα. Οι αλλαγές αυτές ενεργοποιούνται όταν δημοσιευτεί η αντίστοιχη έκδοση κώδικα.

## Περιεχόμενο

Το `aram-catalog-v2` περιέχει συνεπές στιγμιότυπο Firestore των `jewelry`, `portfolio`, `settings`, `orders`, `orderNotifications` και `catalogHistory`, μαζί με τα τμήματα `catalogHistory/*/parts/*`. Περιλαμβάνει και την έκδοση των αρχικών έργων Portfolio ώστε να διατηρούνται seed δεδομένα, overrides και αρχειοθετήσεις κατά την ανάκτηση. Timestamps, bytes, GeoPoints και document references διατηρούν τον τύπο τους.

Αντιγράφονται τα αναφερόμενα δημόσια, ιδιωτικά και αρχικά media, καθώς και όσα αναφέρονται στο ιστορικό. Αρχεία των δύο project buckets αντιγράφονται με συγκεκριμένο generation. Υποστηριζόμενα εξωτερικά media αντιγράφονται με streaming, χωρίς προώθηση διαπιστευτηρίων ή redirects. Μη υποστηριζόμενος ή μη διαθέσιμος σύνδεσμος εμφανίζεται στις ελλείψεις. Τα αρχεία που ανήκουν στο Git/build παραμένουν μέρος του πηγαίου πακέτου.

Το στιγμιότυπο δεδομένων αποθηκεύεται πριν από την αντιγραφή media, ώστε να παραμένει διαθέσιμο ακόμη και αν διακοπεί η μεταφορά. Μόνο όταν αντιγραφούν όλα τα εντοπισμένα media καταγράφεται `mediaIncluded: true` και η ένδειξη «Πλήρες». Αλλιώς το αντίγραφο εμφανίζεται ως «Μερικό», με λίστα ελλείψεων. Τα παλιά `aram-catalog-v1` παραμένουν διαθέσιμα ως «Δεδομένα μόνο».

## Αποθήκευση και διατήρηση

- Τα δεδομένα εναλλάσσονται στις υπάρχουσες 48 θέσεις μισάωρου και 7 ημερήσιες θέσεις στο `backups/catalog/`.
- Τα bytes φυλάσσονται ανεξάρτητα στο `backups/media/`. Ίδιο αρχείο/generation δεν αντιγράφεται ξανά. Υπάρχει προστατευμένο ευρετήριο για αρχεία που αντιγράφηκαν ήδη και αργότερα διαγράφηκαν από τον αρχικό φάκελο.
- Τα αντίγραφα media διατηρούνται ανεξάρτητα από την εναλλαγή των δεδομένων. Δεν διαγράφονται αυτόματα από αυτόν τον κώδικα. Ο αποθηκευτικός χώρος αυξάνεται με τις νέες εκδόσεις αρχείων, όχι με κάθε επανάληψη backup.
- Δεν κληρονομούν δημόσια Firebase download tokens. Η πρόσβαση και οι σύνδεσμοι λήψης του ευρετηρίου απαιτούν admin. Οι υπογεγραμμένοι σύνδεσμοι λήξης πέντε λεπτών αποφεύγουν τα όρια μεγάλων αποκρίσεων Functions.

Η λήψη `.json.gz` περιέχει δεδομένα και ευρετήριο, όχι ενσωματωμένα όλα τα bytes. Η επαναφορά χρειάζεται πρόσβαση και στα ιδιωτικά αντίγραφα Storage. Είναι προστασία από διαγραφή/αλλαγή εγγραφών ή αρχικών media στον ίδιο project bucket· δεν είναι ανεξάρτητο αντίγραφο άλλου παρόχου ή προστασία από διαγραφή ολόκληρου του bucket.

## Έλεγχος επαναφοράς

Το CLI χρησιμοποιεί το υπάρχον server credential `FIREBASE_SERVICE_ACCOUNT` για το `aramcreations-e1529`. Δεν αποθηκεύονται credentials σε αρχεία του repository. Οι ακόλουθες εντολές είναι οδηγίες χρήσης· δεν εκτελούνται από το build ή τα offline tests.

Πρώτα γίνεται μόνο έλεγχος, χωρίς εγγραφές:

```sh
npm run backup:restore -- --file aram-slot-1.json.gz --prefix recovery_drill_
```

Αφού ελεγχθεί το αποτέλεσμα, εφαρμογή σε κενές απομονωμένες συλλογές:

```sh
npm run backup:restore -- --file aram-slot-1.json.gz --prefix recovery_drill_ --apply
```

Αντί τοπικού αρχείου υποστηρίζεται `--backup slot-1.json.gz`. Χωρίς prefix επιλέγεται μοναδικό `recovery_<timestamp>_`. Το CLI ελέγχει όλα τα δεδομένα και τα checksum/generations των αντιγράφων πριν γράψει. Δεν αντικαθιστά υπάρχοντα διαφορετικά media ή μη κενές συλλογές. Οι νέες εγγραφές χρησιμοποιούν create preconditions και διατηρούν ιστορικό, timestamps και κλειδιά idempotency. Τα εξωτερικά media αποκαθίστανται σε διαχειριζόμενο φάκελο και οι αντίστοιχες αναφορές ενημερώνονται συνεκτικά, ακόμη και μέσα σε κατατμημένο ιστορικό.

Για αποκατάσταση μόνο αρχείων υπάρχει `--media-only`. Η εφαρμογή με ελλείψεις απαιτεί ρητά `--allow-partial`. Τα παλιά v1 δεν περνούν ως πλήρης επαναφορά.

Η επιλογή `--production-empty` στοχεύει τις αρχικές συλλογές και πάλι μόνο εφόσον είναι κενές. Σε πραγματική ανάκτηση παραγωγής πρέπει να έχουν σταματήσει checkout και αποστολές ειδοποιήσεων. Πριν ξανανοίξουν, χρειάζεται αντιπαραβολή παραγγελιών με Stripe: ένα παλιότερο στιγμιότυπο δεν ανακαλεί πληρωμές ή emails που έγιναν μετά τη λήψη του. Δεν υπάρχει κοινή ατομική συναλλαγή Firestore/Storage ή όλης της ανάκτησης πολλών batches.

## Ρύθμιση και επαλήθευση

Η υπογραφή αιτημάτων του worker παράγεται από το ήδη διαθέσιμο server credential, χωρίς νέο μυστικό. Το worker δέχεται μόνο υπογεγραμμένη εργασία, ελέγχει λήξη και διπλή εκτέλεση. Για τοπικό Netlify Dev μπορεί να οριστεί `CATALOG_BACKUP_WORKER_URL` στη διεύθυνση της τοπικής background function. Στην παραγωγή χρησιμοποιείται η διεύθυνση του deploy/site. Τα runtime credentials παραμένουν στις ρυθμίσεις της υπηρεσίας.

Οι δοκιμές `server/catalog-backups.test.ts` χρησιμοποιούν απομονωμένο Firestore/Storage και πραγματικά bytes. Ελέγχουν ιδιωτικότητα αντιγράφων, επαναχρησιμοποίηση generations, πλήρες/μερικό αποτέλεσμα, ιστορικό, απώλεια αρχικού, επαναφορά, συγκρούσεις και αλλοίωση. Δεν εκτελούν επαναφορά ή εγγραφές παραγωγής.

Οι έλεγχοι generation και η αντιγραφή βασίζονται στο [Cloud Storage Objects: rewrite](https://cloud.google.com/storage/docs/json_api/v1/objects/rewrite).
